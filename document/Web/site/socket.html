Socket system net.socket.h, net.socket/socket/, build/src/net.socket/

계층 구성

소켓은 인터페이스(net::io::I*: Isocket, Iconnectable, Iconnect_notify, Iconnect_requestable, Isendable, Isend_request, Isender(_datagram), Ireceivable_stream/datagram, Ipacketable, Imessageable, Irestorable)와 N* 컴포넌트의 조합이다. 기본 조합은 net.definitions.socket.h 의 …::tcp::Ndefault.

완성형 소켓(net::socket, <RECEIVE_HEADER_T=uint32_t, SEND_HEADER_T=RECEIVE_HEADER_T>): Itcp(connect_notify 없는 전체 스택), tcp(서버 측 기본, on_message 기본 BYPASS), tcp_client, tcp_client_reconnect(on_request_reconnect(Iconnective*)), tcp_no_gather, tcp_buffered, tcp_queue, tcp_lambda, tcp_restorable, udp(Nudp + binder::Nudp + datagram 계층), udp_resend.

class my_socket : public net::socket::tcp<>
{
    result_code on_message(sMESSAGE_NETWORK& _msg) override;
    void on_connect() override;
    void on_disconnect(uint64_t _reason) override;
    void on_fail_connect(uint64_t _reason) override;             // 클라이언트
    result_code on_request_connect(const net::sockaddr&) ;      // 선택
};
// UDP: on_receive(buffer_view, sockaddr), on_fail_receive, on_receive_exhausted

종료 이유 DISCONNECT_REASON_*: 상위 바이트 플래그(FAIL, ACTIVE, ABORTIVE …) + 하위 코드(OVERFLOW_MAX_MESSAGES, MESSAGE_LENGTH_TOO_LONG, KEEP_ALIVE_TIME_OUT, SUSTAIN_TIMEOUT …). 부가 add_on::Nkeep_alive, Nsocket_sustain. 관리자 connectable_manager::list<T>, list_keep_alive_active / passive.

acceptor · connector · connect_requestable

  • net::acceptor<TSOCKET> = connective::acceptor::Ntcp + Nmessage_transmitter + connectable_manager::list<TSOCKET>. 소켓 할당 process_alloc_connectable(). SSL 특수화 net.acceptor.secure.h(Ntcp_ssl), HTTP net.acceptor.http.h. start() / start(START_PARAMETER) / start(context). 훅 on_request_accept, on_accept(Iconnectable*), on_fail_accept, on_accept_aborted / recovered, on_prepare_socket, on_closesocket, on_starting / on_start / on_stop. accept 되는 소켓의 io_context 는 process_get_connectable_io_context() 로 지정. executable_accept 는 acceptor 를 object_ptr 로 보유(r11388).
  • net::connector<TSOCKET> = connective::connector::Ntcp + list. TSOCKET 이 connect-requestable 이 아니면 CONNECTABLE_SOCKET_TCP<T> 로 감싸 Ntcp_reconnect 를 덧붙인다. 훅 on_request_connect(Iconnectable*, context&), on_disconnect(Iconnectable*, reason). context 키 "connection_list", "socket_option", "enable_progress_log". UDS 지원(r11406).
  • connect_requestable::Ntcp / Ntcp_reconnect: Linux 는 any:0 명시 bind 를 생략(TIME_WAIT 시 0.8 ms/회, 포트 고갈 회피, r11387). bind(any:0) 의 EADDRINUSE 가 묻히던 문제는 r11413.
  • 비상 acceptor net::emergency::acceptor<T> / manager(net.emergency.manager.h): system_executor 와 분리된 자체 executor, 접속당 전용 thread(종료 시 제거). manager::install<TSOCKET>(START_PARAMETER, SETTING) 가 shutdown(Linux SIGTERM/SIGINT, Windows SIGINT), emergency(SIGUSR1 / SIGBREAK: 비상 acceptor 기동), terminate(SIGUSR2 / SIGTERM: 덤프, 접속 강제 종료, _Exit) 를 건다. trigger() 로 코드에서 발생. system_executor::register_destroy_handler 로 정상 종료 시에만 내려간다.

송신

적용된 최적화 기법 전체는 send 최적화 문서.

  • Isender: send(shared_buffer[&&], option), 컨테이너(vector, list, deque, array, circular_list, static_vector) 일괄 send, send(sMESSAGE_BUNDLE), operator<<, datagram send_to(buf, sockaddr). 모두 process_send(buffer, count_message, option) 로 간다.
  • Ntcp_async_gather(기본): 큐의 버퍼를 하나의 sendmsg / WSASend 로 묶는다. 상수 BYTES_SEND_ASYNC_THRESHOLD 4 KB, COUNT_SEND_GATHER_START_DEPTH 16, gather 버퍼 1~64 KB.
  • 큐 한도(Itcp_gather): maximum_depth_of_send_buffer() 4096(2의 거듭제곱), maximum_depth_of_send_buffer_bytes() 8 MB(accept 된 소켓은 4 MB). 보내는 thread 가 가져간 묶음(EPOLLOUT 대기 잔량 포함)은 한도에 세지 않는다(r11361, IOCP 와 동일). 초과 시 process_on_send_overflow → OVERFLOW_MAX_MESSAGES / OVERFLOW_MAX_BYTES.
  • Linux MSG_ZEROCOPY(io_uring 백엔드만): enable_zerocopy(), zerocopy_threshold()(16 KB).
  • send_defer(system/object/send_defer.h): 그룹 락 안 또는 send_defer::scope 안의 send 는 큐잉되어 가장 바깥 락 해제 시 순서대로 flush. send_defer::flush(), enable(false), Isend_deferrable. Ntcp_async_gather(_buffered) 와 Nudp 만 구현. 락 안에서 응답을 기다리는 동기 호출은 scoped_thread_block 또는 flush() 필요. epoll 의 net::io::send_cork 는 한 thread 의 연속 send 를 1회 sendmsg 로 합친다(옛 단일 슬롯 cork API 는 r11362 삭제).

수신 · 프레이밍

적용된 최적화 기법 전체는 Receive 최적화 문서.

  • packetable::Nstream<HEAD=uint32_t>: 오프셋 0 의 크기 필드(헤더 포함 길이)로 메시지를 자르고 process_pre_message → process_message → on_message. 헤더보다 짧으면 INVALID_MESSAGE_TOO_SHORT_LENGTH. 남은 부분 메시지는 다음 read 로 이월. 크기 접근자 message_headerable(int32 at 0), message_headable_primitive<T,N>, definition_message_header<T>(net.definitions.socket.protocol.h). 메시지 타입 필드는 이 계층에 없다.
  • 다른 프로토콜: 헤더 템플릿 타입을 바꾸거나 Ipacketable::process_packet 을 교체(Nstream_json, websocket 의 process_packet_websocket, crypt receivable). messageable::Nqueue 는 즉시 디스패치 대신 큐잉.
  • 한도(net.definitions.socket.h): MAX_TCP_MESSAGE_SIZE 512 MB, MIN_TCP_MESSAGE_SIZE 1 KB, 기본 메시지 버퍼 1 KB(최대 MEMORYPOOL_MAX_SIZE_OF_MEMORY_BLOCK), 수신 큐 256 MB, 수신 버퍼 4 KB~8 MB.
  • 버퍼 성장(receivable::Nstream): MAX_RECEIVE_PER_EVENT 8, MAX_BYTES_RECEIVE_WINDOW_GROWN 64 KB, 작은 수신이 연속 64회면 축소(m_count_receive_small hysteresis, r11345 회귀 수정). 소켓별 minimum/maximum_message_buffer_size(), 전역 default_message_buffer_min_size/max_size, set_default_packet_buffer_size. Linux 소켓 버퍼는 기본 커널 autotuning, net::io::socket::Ntcp::enable_explicit_socket_buffer_size 로 명시 설정.

플랫폼 백엔드

  • Windows: *.iocp.cpp, RIO *.rio.cpp(Nstream_rio, *_rio sendable). loopback fast path api::socket::set_loopback_fast_path(SIO_LOOPBACK_FAST_PATH) 를 acceptor/connector/connect_requestable 에서 호출. Windows TFO 클라이언트는 SYN 에 데이터를 싣는 API 미구현.
  • Linux: *.epoll.cpp. net.socket 에 io_uring 파일은 없고 Executor 의 io_context 백엔드가 담당. 구조·설계 경위·epoll 대비 벤치는 io_uring 백엔드 · Linux 벤치. SOCK_NONBLOCK 생성, accept4, UDP recvmmsg/sendmmsg(r11393~). epoll 핸들은 native handle 과 따로 저장되므로 socket 교체 시 detach / closesocket / address_family / set_epoll_handle 을 모두 바꿔야 한다. connect 완료 처리 중 m_epoll_event_processing_now 로 close 와의 경합을 막는다(r11387).
  • UDS loopback(Linux): enable_uds acceptor 는 TCP 와 함께 추상 주소 "\0cgdk.tcp.<listen port>"(api::socket::make_uds_address) 로도 listen(listen 주소가 any/loopback 일 때만, 실패 시 경고 후 TCP 만). uds_only 는 TCP 를 bind 만 하고 listen 하지 않음. 클라이언트는 connect_requestable::Ntcp::enable_uds_loopback(true) 를 켠 경우에만(기본 off = TCP) loopback(127.x, ::1) 대상에 UDS 먼저, 없으면 TCP. bind_endpoint 지정 시 생략. sockaddr::is_unix(), is_loopback() 은 UDS 도 true, to_string() = "unix". 사용법·동작·성능은 UDS (같은 host 접속) 문서.

ssl · crypt · http · websocket · kafka · mail

  • net::socket::tcp_ssl<>(Nsocket_ssl, ssl_start_handshake(), start_ssl_handshake_timer() 10 s), tcp_crypt<>(CGDK 자체 cryptor, 훅 on_connecting, process_certify_client_info, process_create_cryptor_for_server). connect_requestable::Ntcp_ssl / Ntcp_reconnect_ssl, connective::acceptor::Ntcp_ssl, sendable::Ntcp_crypt*.
  • net::socket::http_server(Nhttp_server, SSL 가능): on_message(sMESSAGE_HTTP_REQUEST&), on_message(sMESSAGE_HTTP_WEBSOCKET&), on_websocket_upgrade(request) false → 403, send_websocket_ping(), body 16 MB. http_client: on_message(sMESSAGE_HTTP_RESPONSE&), body 64 MB, connect/response timeout. net::http_request / Ihttp_request(set_request, request()). 메시지 MSG_HTTP*.h, WEBSOCKET_MESSAGE.h. acceptor/connector 특수화 net.acceptor.http.h, net.connector.http.h.
  • kafka(librdkafka): net::kafka::producer(produce(), produce_to(topic[, partition]), on_delivery), consumer(subscribe / unsubscribe, on_message(sMESSAGE_KAFKA&), on_error). mail: net::email::smtp + smtp::socket(SSL connect_requestable).
