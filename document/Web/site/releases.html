2026.10.22 r11391 ~ r11415

  • 비 TLS factory::object_pool<T> 삭제 (r11415) — 사용처 없음, 통계 TLS 분기가 컴파일되지 않고 Npoolable 과 타입도 맞지 않던 코드. eFACTORY_GC_TYPE::POOLING 은 object_pool_tls 의 gc 모드로 남는다. 삭제 전 측정한 풀 성능 비교(new/delete · tcmalloc · object_pool_tls, 버전별) 를 Pool system 절에 추가.
  • TCP socket option (r11394) — sSOCKET_OPTION_TCP, Isocket::socket_option() / apply_socket_option(): TCP_NODELAY, TCP_QUICKACK, SO_BUSY_POLL, TCP_NOTSENT_LOWAT, TCP Fast Open. 기본값은 아무것도 켜지 않음(TCP_NODELAY 만 종전처럼 true, connectable::Ntcp::m_enable_tcp_nodelay 는 socket_option().tcp_nodelay 로 대체). acceptor "socket_option"·"tcp_fastopen"(Linux 는 sysctl net.ipv4.tcp_fastopen 에 2 필요), connect_requestable·connector "socket_option". START_PARAMETER 구조체 크기 변경 → 사용하는 쪽 전체 재빌드. test_socket_option.cpp 12개, tutorial ex15.
  • io_uring 백엔드 (r11393) — api::io_context_uring, raw syscall, 커널 5.13+, CGDK_IO_URING=1, 불가 시 epoll fallback. executor thread CPU affinity.
  • Linux 소켓 성능 요소 (r11393~r11398) — SOCK_NONBLOCK / accept4, enable_explicit_socket_buffer_size, 수신 버퍼 축소 hysteresis(r11345 이후 recv 당 ~700 B 로 떨어지던 회귀 수정), MSG_ZEROCOPY(io_uring), UDP recvmmsg/sendmmsg, acceptor "cpu_affinity" / "tcp_defer_accept". r11392 이전 Linux UDP 수신 불가 수정. test_linux_io.cpp, bench_linux_io.cpp.
  • 접속 중 close 경합 (r11395~r11397) — SYN 상태 close 와 connect 완료 thread 의 경합을 disconnect 1회로 정리. 풀 재사용 socket 의 socket_option() 초기화(r11400).
  • net.update (r11391) — receiver 작업 직렬 executor 큐, 32 MiB 한도·backpressure, stop 30 s 드레인.
  • 후속 수정 (r11402~r11414) — Ntcp_reconnect 즉시 실패 시 재접속 예약(r11404), accept↔attach 사이 fd 재사용 창(r11414), connector UDS(r11406), 그룹 null 역참조·container 콜백 UAF(r11402, r11409, r11410), object pool 종료 TLS 잔여 누수(r11411~r11412), _buffer_unreal.h 결함 3건(r11408), Linux Release/Debug 동시 configure 시 svn_version.h.tmp 경합(r11403), connector bind(any:0) EADDRINUSE 묻힘 = 부하 시 accept 정체 원인(r11413).

2026.10.21 r11386 ~ r11390

  • net::emergency — 비상 acceptor net::emergency::acceptor<T> 와 signal 처리기 manager(종료 / 비상 / 강제 종료), executor::make_io_context_threads(), acceptor::Ntcp::process_get_connectable_io_context(), examples/1.6.emergency_signal.
  • Linux UDS 같은 host 접속 (r11386~r11390) — acceptor enable_uds / uds_only, 클라이언트 loopback 시 UDS 우선, sockaddr::is_unix(). 측정(Linux): 저부하 지연 p50 16.7 → 9.3 µs, pipeline +26%, 접속 2.2만/s → 17.5만/s(raw 1 thread 접속 TCP 18 µs vs UDS 3.6 µs). UDS 없는 서버로 loopback 접속 시 시도 비용 ~2.5 µs/접속. tutorial ex14, test_uds.cpp 24개.
  • epoll 핸들 수명 버그 (r11387~r11388) — connect 완료 뒤 set_event 와 다른 thread close 의 경합으로 닫힌 fd 번호를 받은 다른 socket 이 SYN 에서 멈춤, SYN/BINDED close 후 m_epoll_handle 잔류로 남의 fd detach, acceptor stop 직후 해제 시 pure virtual call. 진단: /proc/<pid>/fdinfo/<epoll fd> 의 events: 40000000 = ONESHOT 소진.
