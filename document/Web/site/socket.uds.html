UDS (같은 host 접속) net.io.connective.acceptor_tcp, net.io.connect_requestable.tcp, net.io.connective.connector_tcp, api.net.socket (Linux)

같은 host 안의 서버끼리 TCP 대신 Unix domain socket 으로 통신하게 하는 기능이다.

  • Linux 전용. Windows 의 SIO_LOOPBACK_FAST_PATH 에 해당한다.
  • 소켓 클래스와 코드는 그대로다. UDS 로 붙은 소켓도 같은 클래스로 만들어지고 on_connect / on_message / on_disconnect 도 같다.
  • 주소는 여전히 127.0.0.1:port 로 적는다. 엔진이 그 port 의 UDS 로 바꿔 붙는다.
  • 서버와 클라이언트가 둘 다 켜야 UDS 로 붙는다. 기본값은 양쪽 모두 꺼짐이다.

켜는 법

서버 (acceptor)

net::acceptor<socket_server>::START_PARAMETER parameter;
parameter.local_endpoint = net::ip::tcp::endpoint{ net::ip::address_v6::any(), 20000 };
parameter.enable_uds = true;     // TCP 와 함께 UDS "\0cgdk.tcp.20000" 로도 받는다
// parameter.uds_only = true;    // UDS 로만 받는다 (TCP port 는 bind 만, listen 안 함)
pacceptor->start(parameter);

설정 파일(context)로는 같은 이름의 키를 쓴다.

{ "local_endpoint": { "port": 20000 }, "enable_uds": true }     // 또는 "uds_only": true

클라이언트

// 프로세스에서 한 번. 이후 loopback 주소로의 모든 접속이 UDS 를 먼저 시도한다.
net::io::connect_requestable::Ntcp::enable_uds_loopback(true);

psocket->start({ net::ip::tcp::endpoint{ net::ip::address_v4::loopback(), 20000 } });
// 붙은 뒤 확인
bool is_uds = psocket->remote_endpoint().is_unix();
설정기본값설명
START_PARAMETER::enable_uds / "enable_uds"falseTCP 와 함께 UDS 로도 listen
START_PARAMETER::uds_only / "uds_only"falseUDS 로만 listen. 외부에서 TCP 로 접속 불가
connect_requestable::Ntcp::enable_uds_loopback(bool)falseloopback 접속 시 UDS 먼저 시도. 프로세스 전역

클라이언트 기본값은 처음 들어갈 때(r11386) true 였고 r11440 에서 false 로 바꿨다. 켜지 않으면 서버가 UDS 로 listen 해도 TCP 로 붙는다.

동작

이름 규칙

  • 추상 이름(abstract namespace) "\0cgdk.tcp.<실제 listen port>". 파일이 생기지 않고 프로세스가 죽으면 이름도 사라진다.
  • 이름은 api::socket::make_uds_address(port, ...) 한 곳에서 만든다. 서버와 클라이언트가 같은 함수를 쓴다.
  • port 가 재할당되면(reallocate_port_at_duplicate_port_error) 바뀐 port 로 이름을 만든다.

서버

  • enable_uds : listen 주소가 any(0.0.0.0, ::) 나 loopback 일 때만 UDS 로도 받는다. 특정 외부 주소면 무시한다.
  • UDS listen 이 실패하면 경고 로그를 남기고 TCP 로만 동작한다. 같은 port 의 UDS 를 이미 다른 프로세스가 쓰는 경우다.
  • uds_only : TCP 소켓은 bind 만 하고 listen 하지 않는다. SO_REUSEADDR 를 꺼서 port 를 독점한다. TCP 접속은 ECONNREFUSED.
  • uds_only 에서 UDS 가 실패하면 소켓을 닫고 예외를 던진다(시작 실패). 주소 제한은 없다.
  • 시작 로그에 listen on UDS 'cgdk.tcp.<port>' 가 찍힌다. stop() 은 TCP 와 UDS 를 함께 닫는다.
  • Windows 는 두 설정을 경고 후 무시하고 TCP 로 동작한다.

클라이언트

  • 대상이 loopback(127.x.x.x, ::1)이고 스위치가 켜져 있으면 먼저 그 port 의 UDS 로 connect 한다. UDS connect 는 즉시 성공하거나 즉시 실패한다.
  • 성공하면 TCP 핸들을 UDS 핸들로 바꾼다. 실패하면 원래대로 TCP 로 접속한다.
  • bind_endpoint 를 지정하면 시도하지 않는다. 단 any:0 은 지정하지 않은 것으로 본다.
  • connective::connector(다중 접속기)도 같은 규칙과 같은 스위치로 UDS 를 쓴다(r11406).
  • 서버에 UDS 가 없을 때 시도 비용은 접속당 약 2.5 µs 다. TCP loopback connect+close 는 약 18.5 µs.

UDS 소켓 구분

  • net::sockaddr::is_unix() 가 true. to_string() 은 "unix".
  • is_loopback() 도 true 다. loopback 으로 판단하는 기존 코드가 그대로 동작한다.
  • 대입과 비교는 AF_UNIX family 를 유지한다. 주소 조회는 family 만 남기고 경로는 넣지 않는다.

UDS 에 적용되지 않는 것

  • TCP socket option(TCP_NODELAY, TCP_QUICKACK, SO_BUSY_POLL, TCP_NOTSENT_LOWAT, TFO). apply_socket_option() 이 건너뛴다.
  • MSG_ZEROCOPY 송신(AF_INET/AF_INET6 만).
  • epoll busy poll. UDS 는 NAPI ID 가 없어 효과가 없다.
  • 공인 주소 조회(socket_address_in_public).

함께 고친 버그

UDS 접속 벤치에서 드러났지만 TCP 에도 있던 epoll 소켓 버그들이다.

  • 즉시 성공한 connect : connect() 가 바로 0 을 돌려주면 epoll attach 없이 이벤트만 바꿔 수신을 못 받았다. 즉시 성공도 진행 중처럼 attach 한 뒤 EPOLLOUT 으로 완료한다.
  • any:0 bind : connect 전에 any:0 을 명시 bind 해 TIME_WAIT 가 많으면 bind 0.8 ms·port 고갈. Linux 는 bind 를 생략한다(r11387, r11413).
  • 닫은 fd 의 epoll 핸들 : SYN·BINDED 상태 close 가 fd 를 닫고 epoll 핸들을 지우지 않아, 소멸자가 재사용된 남의 fd 를 detach·close 했다(r11387).
  • 접속 완료와 close 경합 : on_connect 뒤 이벤트 재설정 사이에 다른 thread 가 close 하면 재사용된 fd 의 남의 executable 을 바꿔치기했다. 처리 중 표시로 close 를 큐에 넣는다(r11387, r11395~r11397).
  • acceptor 수명 : accept executable 이 acceptor 를 raw 포인터로 들어 stop() 직후 해제하면 pure virtual 호출(r11388). 처리 중 accept 를 세어 stop 이 기다리게 했다(r11418).
  • 풀 객체 필드 : accept executable 은 풀에서 재사용된다. UDS 용 필드를 TCP 경로에서 초기화하지 않아, UDS 를 쓴 뒤 TCP acceptor 가 닫힌 UDS fd 에서 accept 했다.
핸들을 UDS 로 바꿀 때는 detach, closesocket, address family, epoll 핸들을 모두 바꿔야 한다. epoll 핸들은 native handle 과 따로 저장된다. 풀 객체에 필드를 넣으면 모든 할당 경로에서 초기화한다.
