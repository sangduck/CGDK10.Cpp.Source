Log system system/object/log.*, server.log.h, server.system/log/

기록 (system)

  • 스트림 매크로 LOG_INFO << "..."sv;, LOG_ERROR, LOG_WARNING, LOG_DEBUG, LOG_FATAL, LOG_SYSTEM, LOG_PROGRESS, LOG_USER, LOG_INFO_LOW. 포맷형 LOG_FMT(target, type, level, ...), LOG_STREAM, LOG_IF / LOG_FMT_IF. 각 매크로는 _ENABLE_LOG_* 로 컴파일 제외 가능.
  • 기본 대상 get_default_logger() / set_default_logger() / reset_default_logger(), DEFAULT_LOGGER. 서비스는 Nstatic_service_logger::get_logger()(logger_hub).
  • 인터페이스 Ilogger::process_log(object_ptr<LOG_RECORD>&&), Ilog_filter::process_filtering(), Ilog_source / log_source. log_type_t {info, progress, debug, fatal, error, warning, user, system}, log_level_t(int: lower -256, normal 0, higher/important 256).

server.log 사용

구성 : server.log.h 하나를 포함하면 CGDK10.server.log 라이브러리가 자동 링크된다(net.socket 포함). Slack 로거만 server.log.slack.h 를 따로 포함한다.

로그 한 건의 흐름

  • LOG_INFO << ... 가 LOG_RECORD(풀 객체, trace 뒤 불변)를 만들어 Ilogger::trace() 로 넘긴다.
  • 로거는 자기 log_filter 로 거른다. 통과하면 process_log().
  • 기본 로거는 logger_hub_archive 다. 락프리 MPSC 큐에 쌓고 executor 에서 한꺼번에 꺼내 자식 로거에 같은 record 를 전달한다. 호출 thread 는 기다리지 않는다.
  • 자식(logger_file, logger_console, logger_socket, logger_slack)은 Nlogger_async 다. 자기 큐에 모았다가 process_log_batch() 로 배치 처리한다. 파일 로거는 배치마다 한 번의 동기 write.
  • 완료는 destroy() 에서만 보장한다. 종료 때 Nstatic_service_logger::reset_logger() 가 기본 hub 를 destroy 해 자식까지 비운 뒤 서비스가 로거를 놓는다.

코드로 만들기 (tutorials/server.1.log)

// log.01 : 파일 로거 하나
auto plogger = make_own<logger_file>();
plogger->initialize({ "./test_log_file.log"sv });          // INITIALIZE_PARAMETER{filename, path, backup_path, ...}
LOG(plogger, log_type_t::info) << "This paragraph is log"sv;

// log.05 : hub 아래에 콘솔 + 파일
auto pconsole = make_own<logger_console>();  pconsole->initialize();
auto pfile    = make_own<logger_file>();     pfile->initialize({ "./test_log_hierarchy.log"sv });
auto phub     = make_own<logger_hub_archive>();
phub->register_log_targetable(pconsole);
phub->register_log_targetable(pfile);
phub->initialize();
LOG(phub, log_type_t::info) << "This paragraph is log"sv;

// log.06 : 기본 로거로 등록하면 대상 없이 LOG_* 매크로만 쓴다
set_default_logger(pconsole);
LOG_INFO << "This paragraph is log"sv;
LOG(log_type_t::system) << log_level_t::higher() << "important"sv;
reset_default_logger();

설정으로 만들기 : Nservice / Nservice_application 은 "service"."logger" 또는 최상위 "logger" 아래의 항목마다 create_logger(type) 로 만들어 기본 hub 에 붙인다. 이름은 키, 종류는 "type". hub 도 "child" 로 자식을 설정으로 만든다.

"logger": {
  "main": { "type": "file", "path": "./log", "filename": "server_{}{}{}.log",
            "recreation": true, "interval": 60, "origin_time_type": "day_begin",
            "create_new": false, "char_encoding": "utf8",
            "filter": { "debug": { "range_level_min": 0 }, "info": { "range_level_min": -256 } } },
  "con":  { "type": "console" },
  "evt":  { "type": "system" }
}
  • "type" : "file"(기본) · "console" · "system"(Windows 이벤트 로그 / Linux syslog) · "socket" · "syslog" · "slack"(server.log.slack.h 포함 시). register_logger_creator() 로 추가.
  • 공통 "filter" : 타입(info / progress / debug / fatal / error / warning / user / system)마다 range_level_min/max, range_origin_min/max, range_source_min/max, range_destination_min/max.
  • logger_file : filename(시간 자리 {}), path, backup_path, recreation / interval(분), origin_time_type(now · minute_begin · hour_begin · day_begin · week_begin · month_begin · year_begin · specified), origin_time, create_new, char_encoding, limit_bytes / limit_lines, instant_open / instant_close_delay.
  • 서비스가 로거를 만들기 전에 쌓인 로그는 logger_hub_archive 가 보관했다가 새 로거에 다시 흘려 준다(get_stored_log()).

규칙

  • LOG_RECORD 는 trace 뒤 바꾸지 않는다. 고쳐야 하면 새 record 로 바꿔 끼운다.
  • set_filter() 는 옛 필터를 로거가 죽을 때까지 보관한다. 로거가 락 없이 필터를 읽기 때문이다(r11338). 필터를 자주 바꾸는 코드는 피한다.
  • 파일 재생성은 백업(name_1.ext…)을 덮어쓰지 않고, 쓰기 실패는 실패가 이어지는 동안 한 번만 기록한다.
  • logger_socket 은 연결 전 로그를 버린다. 원격 로거가 필요하면 접속 뒤에 등록한다.

비용 (Release) : 기본 구성(logger_hub_archive → logger_file)에서 첫 LOG_INFO 부터 hub·파일 로거 destroy() 로 파일 쓰기가 끝날 때까지의 시간을 로그 수로 나눈 값. 5회 중앙값의 두 실행 범위. Windows · Linux 8 코어는 HEAD r11463, Linux 32 코어는 r11478.
