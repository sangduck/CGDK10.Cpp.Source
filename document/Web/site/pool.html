Pool system system/object/factory.*, Npoolable.h, definitions.factory*.h

  • Npoolable<T> — 정적 get_factory()(default_factory_pool_t<T>), alloc(), dealloc(). process_dispose() 가 객체를 풀로 돌려보낸다. make_object<T> 는 T 가 Npoolable 이면 T::alloc() 을 쓴다.
  • default_factory_pool_t<T> = factory::object_pool_tls<T>(definitions.factory.h:30). 비 TLS factory::object_pool<T> 는 사용처가 없고 통계 TLS 분기가 컴파일되지 않는 상태였으므로 r11415 에서 삭제.

object_pool_tls<T>

  • thread 마다 풀별 sTLS_DATA(64바이트 정렬)에 TLS 스택을 두고 thread_local m_tls_data[54] 로 선택.
  • 뒤에 중앙 스택 LOCKFREE_SELF_STACK<T*>. 이 매크로는 현재 모든 플랫폼에서 locked_self_stack 으로 매핑된다(sharded_self_stack 도 있으나 채택 안 됨).
  • TLS ↔ 중앙 이동은 chain 단위 배치: 크기 = TLS_BATCH_BYTES(64 KiB) / sizeof(T), 상한 TLS_BATCH_MAX = 32(r11348).
  • API: prepare(n), shrink(n), sustain(eFACTORY_GC_LEVEL), stacked_count().
  • GC: eFACTORY_GC_TYPE {NO_POOLING, POOLING, POOLING_NO_GC, TLS_POOLING(기본), TLS_POOLING_NO_GC}. schedulable::system::factory_sustain 이 주기적으로 돌며 thread idle 시 thread 별로 정리(r9719). system_executor::start_factory_garbage_collection() 으로 켠다. 종료 시 TLS 잔여 객체 누수는 r11411 에서 수정.
  • 팩터리 종류 eFACTORY_TYPE {POOL_MEMORYBLOCK, POOL_SYSTEM, POOL_USER}. 등록부 factory::manager, print_statistics().

memory_block

factory::memory_block 은 size-class 메모리 풀. 균등/배율 프리셋(TINY ~ HUGE, 최대 1 MB)이 definitions.factory.pool.memory_block.h 에 정의되어 있고, alloc_shared_buffer(size) / mem_pool_alloc / mem_pool_free 가 이 풀을 쓴다. 소켓 수신 버퍼의 최대 크기 MEMORYPOOL_MAX_SIZE_OF_MEMORY_BLOCK 도 여기서 온다.

통계

statistics::factory / unit_factory / unit_factory_tls, sSTATISTICS_TLS. _USE_TLS_FACTORY_STATISTICS 가 켜져 있어 thread 별 풀 통계를 모은다(factory::object 통계 TLS 는 r11412). 벤치: unit_test.object.bench.object_pool, bench.mem_tcmalloc(Windows).

성능 비교

측정 조건

  • 객체 : payload 48 B. 실제 크기는 Npoolable 풀 객체 128 B, new/delete 는 64 B 구조체(MSVC 기준).
  • 빌드 : Release. MSVC v145 /O2, g++ 15.2 -O3.
  • 머신 : Windows 24 코어 데스크톱, Linux 32 코어 서버(Ubuntu 26.04).
  • 값 : 항목마다 5회 중앙값을 2회 돌려 다시 중앙값.
  • 같은 thread : alloc 직후 같은 thread 가 dealloc.
  • 교차 thread : A 가 alloc 한 객체를 SPSC 링으로 넘겨 B 가 dealloc. 로직 thread 할당 → I/O thread 해제 패턴.
  • new/delete : 각 플랫폼 기본 할당자(UCRT heap, glibc malloc). CGDK 와 무관한 독립 바이너리. thread 간 공유 변수 없음(포인터는 컴파일러 배리어로만 유지).
  • tcmalloc : gperftools 2.10(Windows, vcpkg) / 2.18(Linux) 의 tcmalloc_minimal.

  • 같은 thread
    object_pool_tls 는 크기와 무관하게 3 ~ 6 ns 다. 포인터만 돌려주므로 크기가 비용에 들어가지 않는다.
    기본 할당자는 Windows 19 ns(4 KB 까지). Linux 는 1 KB 까지 4 ns, 4 KB 부터 20 ns(glibc tcache 상한 초과).
    glibc 는 64 KB 이상도 20 ns 다. 64 KB 는 mmap 임계값(128 KB) 아래라 heap 에서 꺼낸다. 128 KB 이상은 처음 한 번 mmap 으로 받지만 그 청크를 free 할 때 임계값이 동적으로 올라가(최대 32 MB) 그 뒤로는 heap 에서 꺼낸다. free 된 청크가 top chunk 에 합쳐져 다음 할당이 포인터 조작뿐이다.
    tcmalloc 은 2.3 ~ 6.5 ns 로 크기 영향이 작다.
  • 64 KB 이상
    Windows 기본 heap 은 다중 thread 에서 1.5 ~ 25 µs(64 KB) · 1.8 ~ 11 µs(128 KB) 로 무너진다. 큰 블록은 LFH 밖이라 heap 락을 탄다. 256 KB 는 단일 thread 도 4.6 µs, 16 thread 107 µs 다(VirtualAlloc 경로).
    tcmalloc 은 같은 thread 는 6 ~ 7 ns 를 지키지만 교차 thread 는 Windows 7 ~ 31 µs, Linux 0.4 ~ 3.1 µs 다.
    object_pool_tls 는 같은 thread 3 ~ 8 ns 를 유지한다. 교차 thread 는 1쌍 190 ~ 230 ns, 4쌍 1,500 ~ 2,700 ns 로 나빠진다.
    원인은 chain 크기다. chain = TLS_BATCH_BYTES(64 KiB) / sizeof(T) 라 64 KB 객체는 chain 이 1개가 되어 교차 해제마다 중앙 락을 탄다. 4 KB 는 chain 16개로 128 ~ 152 ns.
    64 KB · 128 KB · 256 KB 모두 chain 1개라 값이 비슷하다. 큰 객체에 chain 최소 개수를 두면 줄일 수 있다.
  • 교차 thread
    4 KB 까지는 object_pool_tls 가 40 ~ 70 ns 로 가장 빠르다. 64 KB 이상에서도 가장 빠르지만 절대값은 200 ns ~ 2.7 µs 다.
    tcmalloc 은 4쌍에서 340 ~ 1,050 ns. 기본 할당자는 Windows 150 ~ 200 ns, Linux 300 ~ 400 ns.

리비전 사이에 들어간 변경과 효과

  • r11283 원자 연산 정리 (r11200 → r11319 구간)
    통계 카운터를 relaxed 원자 연산으로. 참조 카운트를 add_ref relaxed · release acq_rel 로. 싱글턴 공개를 acquire/release 로.
    효과 : Linux 같은 thread 4.62 → 2.17 ns. seq_cst 원자 연산은 x86 에서 full fence 라 Linux 에서 특히 비쌌다.
    Windows 와 교차 thread 는 변화 없음.
  • r11336 chain 배치 이동 (r11319 → r11414 구간)
    TLS 스택 ↔ 중앙 스택 이동을 객체 하나씩에서 chain(64 KiB / sizeof(T), 최대 32개) 단위로.
    해제 전용 thread 도 chain 크기만큼 TLS 에 모았다가 한 번에 반환.
    중앙 스택의 std::mutex 를 4바이트 CAS + atomic wait 락으로.
    효과 : 매 alloc/free 가 타던 중앙 락이 chain 당 한 번이 됐다. 교차 thread Windows 68 → 46 ns · 464 → 61 ns, Linux 189 → 42 ns · 825 → 55 ns. 쌍 수가 늘어도 평평하다.
    같은 thread 도 Windows 에서 약 20% 빨라졌다(코드 배치 변화).
  • r11348 풀 해제 후 접근 수정
    종료 때 객체 삭제가 풀의 마지막 참조를 놓으면 풀이 지워진 뒤 통계를 쓰던 use-after-free. 삭제 직전 풀을 잡아 두는 방식으로 수정.
    정확성 수정. 성능 변화 없음.
  • r11411 · r11412 TLS data 소유 모델
    고친 문제 1 : close 뒤 TLS 스택에 남은 객체가 종료까지 해제되지 않던 누수.
    고친 문제 2 : 같은 T 의 풀·팩토리를 다시 만들면 thread 의 thread_local 포인터가 지워진 data 를 가리키던 use-after-free.
    방법 : sTLS_DATA 를 thread 와 풀이 공동 소유(refs 2). _get_tls_data() 가 소유자를 확인.
    비용 : 그 확인(load 1회 + 비교 1회)이 Linux 같은 thread 에서 r11319 대비 0.2 ~ 0.3 ns. 3달 전보다는 빠르다. 교차 thread 와 make_object 는 변화 없음.

정리

  • 교차 thread 4 ~ 15배, 같은 thread Windows 약 20% · Linux 약 48% 개선.
  • 정확성 수정 두 건(r11348, r11411·r11412)의 비용은 측정 오차 안.
  • 남은 개선 지점 : 64 KB 같은 큰 객체의 교차 thread 경로. chain 이 1개가 되지 않도록 chain 최소 개수를 둔다.

테스트 코드

위 표를 만든 하네스. 64 B 표는 같은 하네스의 burst 16·2 쌍 항목을 더한 판이고, 리비전 비교는 같은 코드를 각 리비전의 헤더·라이브러리로 빌드한 것이다.

size_bench.cpp (펼치기) 
// size bench : payload 64B .. 256KB, new/delete (or tcmalloc when linked with -DUSE_TCMALLOC) vs CGDK::object_pool_tls
// - no zero-init (the pool reuses objects without re-constructing them), the pointer is kept alive with a compiler barrier only (no shared variable between threads)
// - cross-thread : producer allocs and pushes into an SPSC ring, consumer pops and frees. in-flight objects per pair limited to 16,384 / 64 MB
#define UNW_LOCAL_ONLY
#define _CGDK_NO_ASSERT_ON_BOUND_CHECK
#include <string>
#include <vector>
#include <memory>
#include <span>
#include <map>
#include <thread>
#include <atomic>
#include <chrono>
#include <algorithm>
#include <cstdio>
#include "cgdk/sdk10/system.object.h"
#ifdef USE_TCMALLOC
#include <gperftools/tcmalloc.h>
#endif

using namespace CGDK;

template <size_t P> struct obj_raw { char data[P]; };
template <size_t P> class obj_tls : public Npoolable<obj_tls<P>> { public: char data[P]; };

#if defined(__GNUC__)
static inline void escape(void* p) { asm volatile("" : : "r"(p) : "memory"); }
#else
static inline void escape(void*) {}
#endif

template <size_t P> struct A_NEW { using T = obj_raw<P>; static T* alloc() { auto p = new T; escape(p); return p; } static void free(T* p) { escape(p); delete p; } };
template <size_t P> struct A_TLS { using T = obj_tls<P>; static T* alloc() { return T::alloc(); } static void free(T* p) { T::dealloc(p); } };

static double now_ns() { return std::chrono::duration<double, std::nano>(std::chrono::steady_clock::now().time_since_epoch()).count(); }

template <class F>
static double median_of(int _repeat, F&& _f)
{
	std::vector<double> v;
	for (int i = 0; i < _repeat; ++i) v.push_back(_f());
	std::sort(v.begin(), v.end());
	return v[v.size() / 2];
}

template <class A>
static double bench_same_thread(int64_t _pairs)
{
	for (int i = 0; i < 1000; ++i) { auto p = A::alloc(); A::free(p); }
	auto t0 = now_ns();
	for (int64_t i = 0; i < _pairs; ++i) { auto p = A::alloc(); A::free(p); }
	return (now_ns() - t0) / double(_pairs);
}

template <class A>
static double bench_mt_same_thread(int _threads, int64_t _pairs)
{
	std::atomic<bool> go{ false };
	std::vector<std::thread> th;
	std::vector<double> ns(_threads);
	for (int i = 0; i < _threads; ++i)
		th.emplace_back([&, i]() { while (!go.load()) {} ns[i] = bench_same_thread<A>(_pairs); });
	go.store(true);
	for (auto& t : th) t.join();
	std::sort(ns.begin(), ns.end());
	return ns[ns.size() / 2];
}

template <class T, size_t N>
struct spsc_ring
{
	T* slots[N];
	alignas(64) std::atomic<size_t> head{ 0 };
	alignas(64) std::atomic<size_t> tail{ 0 };
	bool push(T* p) { auto t = tail.load(std::memory_order_relaxed); if (t - head.load(std::memory_order_acquire) == N) return false; slots[t & (N - 1)] = p; tail.store(t + 1, std::memory_order_release); return true; }
	T* pop() { auto h = head.load(std::memory_order_relaxed); if (h == tail.load(std::memory_order_acquire)) return nullptr; auto p = slots[h & (N - 1)]; head.store(h + 1, std::memory_order_release); return p; }
};

template <class A, size_t RING>
static double bench_cross_thread(int _pairs, int64_t _objects)
{
	using T = typename A::T;
	std::vector<std::unique_ptr<spsc_ring<T, RING>>> rings;
	for (int i = 0; i < _pairs; ++i) rings.push_back(std::make_unique<spsc_ring<T, RING>>());
	std::atomic<int> ready{ 0 };
	std::atomic<bool> go{ false };
	std::vector<std::thread> th;
	for (int i = 0; i < _pairs; ++i)
	{
		auto* r = rings[i].get();
		th.emplace_back([&, r]() { ++ready; while (!go.load()) {} for (int64_t n = 0; n < _objects;) { auto p = A::alloc(); while (!r->push(p)) {} ++n; } });
		th.emplace_back([&, r]() { ++ready; while (!go.load()) {} for (int64_t n = 0; n < _objects;) { auto p = r->pop(); if (p == nullptr) continue; A::free(p); ++n; } });
	}
	while (ready.load() != _pairs * 2) {}
	auto t0 = now_ns();
	go.store(true);
	for (auto& t : th) t.join();
	return (now_ns() - t0) / double(_objects);
}

template <size_t P, template <size_t> class A>
static void run(const char* _name)
{
	const int R = 3;
	constexpr size_t RING = ((64u * 1024 * 1024) / P < 16384) ? (64u * 1024 * 1024) / P : 16384;	// in-flight objects per pair
	printf("%-16s %7zu : same1t %9.2f  same4t %9.2f  same16t %9.2f  cross1 %9.2f  cross4 %9.2f\n", _name, P,
		median_of(R, [] { return bench_same_thread<A<P>>(2'000'000); }),
		median_of(R, [] { return bench_mt_same_thread<A<P>>(4, 500'000); }),
		median_of(R, [] { return bench_mt_same_thread<A<P>>(16, 200'000); }),
		median_of(R, [] { return bench_cross_thread<A<P>, RING>(1, 500'000); }),
		median_of(R, [] { return bench_cross_thread<A<P>, RING>(4, 200'000); }));
	fflush(stdout);
}

template <size_t P> static void run_size()
{
#ifdef USE_TCMALLOC
	run<P, A_NEW>("tcmalloc");
#else
	run<P, A_NEW>("new/delete");
#endif
	run<P, A_TLS>("object_pool_tls");
}

int main(int, char**)
{
#ifdef USE_TCMALLOC
	printf("[tcmalloc %s]\n", tc_version(nullptr, nullptr, nullptr));
#endif
	printf("%-16s %7s : ns/pair same-thread 1t/4t/16t, ns/object cross-thread 1/4 pairs\n", "allocator", "bytes");
	run_size<64>();
	run_size<128>();
	run_size<1024>();
	run_size<4096>();
	run_size<65536>();
	run_size<131072>();
	run_size<262144>();
	return 0;
}
