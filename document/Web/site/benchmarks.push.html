큰 묶음 push 처리량 examples/1.1.tcp_echo · 100 소켓 · 8 B 메시지 · Linux epoll 회귀와 수정 (r11344 → r11371 → r11471)

예제 tcp_echo 의 트래픽 테스트로 "100 소켓이 8 B 메시지를 초당 몇 개까지 안정적으로 주고받는가" 를 쟀다. epoll 송수신 최적화(r11345) 전후를 비교하다가 Linux 에서 메시지당 CPU 회귀를 찾았다. 원인 두 가지를 r11371(수신)과 r11471(송신)에서 고쳤다. 이 문서는 측정 방법, 결과, 원인 분석, 재현 방법을 정리한다.

요약
  • 지금(r11471) : Linux 32 코어 서버 B 에서 회당 320만 개, 초당 3.2억 메시지까지 끊긴 소켓 0. 메시지당 CPU 는 서버 0.041 µs, 클라이언트 0.014 µs 로 r11344(0.040 / 0.010)와 같은 수준이다.
  • 회귀 구간(r11345 ~ r11470) : 같은 처리량에 메시지당 CPU 가 서버 1.7 ~ 2배, 클라이언트 7 ~ 9배였다. 회당 240만 개부터 클라이언트 CPU 가 포화되어 연결이 끊겼다.
  • 원인 1, 수신(r11371 에서 수정) : 1 KB 수신 버퍼가 커지지 않아 recv 한 번에 약 700 B 만 받았다.
  • 원인 2, 송신(r11471 에서 수정) : send cork 가 send 마다 시각을 읽고 20 µs 마다 flush 해서, 받은 큰 묶음을 3.4 KB 씩 잘라 보냈다.
  • Windows(IOCP) : 두 코드 경로를 쓰지 않아 해당 없다. 24 코어 데스크톱에서 약 8,000만/s 까지 안정이고, 그 위는 서버 CPU 가 포화된다.
  • 교훈 : 회당 160만 개까지는 처리량이 똑같았다. 메시지당 CPU 를 같이 재지 않았다면 놓쳤을 회귀다.

측정 구성

  • 서버 : net::socket::tcp_buffered<> echo. on_message 에서 받은 버퍼를 그대로 send 한다(아래 bench_server_main.cpp).
  • 클라이언트 : 예제 클라이언트 examples/1.1.tcp_echo/client/console/echo_client.cpp 를 그대로 쓰고, 키 입력 대신 인자로 동작하게 main 만 바꿨다(bench_client_main.cpp).
  • 트래픽 : 예제의 트래픽 테스트다. 약 1초마다 소켓마다 8 B 메시지 N 개를 버퍼 하나로 보낸다(이전 회차가 끝났을 때). 제공량은 100 × N 개/s 다. 버퍼 하나는 최대 2,097,152 개(16 MB)라, N = 320만이면 16 MB 와 8.8 MB 를 연달아 보낸다.
  • 지표 : echo 되어 돌아온 메시지 수/초(recv_msg/s), 끊긴 소켓 수(송신 실패), 메시지당 CPU. 메시지당 CPU 는 측정 구간의 프로세스 CPU 시간(utime + stime)을 받은 메시지 수로 나눈 값이다.
  • 측정 구간 : 접속과 2초 워밍업 뒤 10초. 클라이언트가 구간 시작과 끝에 MEASURE_BEGIN / MEASURE_END 를 찍으면 실행 스크립트가 그때 /proc/<pid>/stat 을 읽는다(Windows 는 Process.TotalProcessorTime).
  • 클라이언트 송신 큐 한도 32 MB(Itcp_gather::default_maximum_queued_bytes) : 기본 8 MB 면 회당 100만 개(8 MB) 이상에서 큐 한도가 먼저 걸려 처리 능력과 섞인다. 서버(accept 된 소켓)는 기본 4 MB 그대로다.
  • 교대 : 비교할 빌드를 번갈아 2 ~ 3회 돌리고 중앙값을 쓴다. 다른 벤치나 컴파일이 돌고 있으면 기다렸다가 시작한다.
  • syscall 수 : strace -c -f 로 처음부터 끝까지 센다(ptrace_scope=1 이라 -p 로 붙을 수 없다). strace 는 처리량을 떨어뜨리므로(r11461, 회당 80만 개 : 8,000만 → 4,480만/s) 횟수를 받은 메시지 100만 개당으로 나눠 비교한다.

원인 1 : 수신 버퍼가 1 KB 에서 커지지 않았다 (r11345 → r11371)

  • r11344 : 이벤트마다 FIONREAD 로 쌓인 양을 묻고, 그 크기로 새 버퍼를 할당해 한 번에 받았다(recv 한 번에 수백 KB).
  • r11345 : FIONREAD 와 이벤트마다의 할당·복사를 없앴다. 처리하지 않은 데이터 뒤의 빈 공간(tail)에 바로 recv 하고, 창을 다 채우면 한 이벤트에서 최대 8번(MAX_RECEIVE_PER_EVENT) 더 받는다.
  • 결함 : _process_prepare_receive_buffer 는 아래 순서로 검사했다. "창을 다 채워 받았으면 8배" 규칙은 마지막 단계에만 있었다.
    1. 남은 데이터가 0 이고 이 소켓만 버퍼를 참조하면 앞으로 되감는다.
    2. 빈 공간이 충분하면 그대로 쓴다.
    3. 혼자 쓰는 버퍼이고 용량이 충분하면 남은 조각을 memmove 로 앞으로 당긴다.
    4. 새로 할당한다. "창을 다 채워 받았으면 8배" 규칙은 여기에만 있었다.
    8 B 메시지는 처리 끝에 남는 것이 거의 없어 늘 1 ~ 3 단계에서 돌아갔다. 그래서 버퍼가 시작 크기 1 KB(DEFAULT_BYTES_TCP_MESSAGE_BUFFER)에서 커지지 않았다.
  • 결과 : recv 한 번에 약 700 B. 이벤트마다 1 KB 이하를 8번 받고 다시 등록(epoll_ctl)하고 기다렸다(epoll_wait). r11360 클라이언트의 recvfrom ÷ epoll_ctl 이 7.95 다.
  • 수정(r11371) : 창을 다 채워 받았으면 먼저 8배로 키운다(1 KB → 8 KB → 64 KB, MAX_BYTES_RECEIVE_WINDOW_GROWN). 줄이는 것은 작은 수신이 64번(COUNT_SMALL_RECEIVES_TO_SHRINK) 이어진 뒤에만 한다. 자세한 규칙은 Receive 최적화.

원인 2 : send cork 가 시각을 너무 자주 읽고 너무 일찍 보냈다 (r11345 → r11471)

  • send cork(r11345, epoll) : 받은 메시지를 처리하면서 같은 소켓에 보내는 응답을 모았다가, 처리가 끝나면 한 번의 sendmsg 로 보낸다. 처리가 오래 걸리는 핸들러에서 응답이 너무 늦지 않도록, 가장 오래 모은 send 가 SEND_CORK_DURATION(20 µs)을 넘으면 바로 보냈다.
  • 비용 1 : 그 나이를 send 마다 chrono::tick::now()(vdso clock_gettime)로 확인했다. 8 B echo 서버 perf 의 14.6% 였다.
  • 비용 2 : 한 번에 받은 큰 묶음(64 KB 창 하나에 8천 개)을 처리하는 데 20 µs 보다 오래 걸린다. 그래서 약 450 개(3.4 ~ 3.6 KB)마다 보냈고, 클라이언트는 작은 조각을 많이 받아 recv · epoll_wait 가 늘었다.
  • 수정(r11471) : 두 sendable(Ntcp_async_gather, Ntcp_async_gather_buffered)의 epoll 경로.
    • 나이 확인 간격을 송신 속도에 맞춘다. cork 를 시작할 때 간격은 1 이다. 확인할 때마다 다음 간격 = 지금 간격 × min(SEND_CORK_DURATION/8, 남은 시간) ÷ 지금 간격에 걸린 시간이고, 1 ~ 32(SEND_CORK_CHECK_MAX)로 자른다.
    • 그래서 echo 처럼 빠른 송신은 32번에 한 번, 메시지 처리가 오래 걸리면 매번 시각을 읽는다.
    • SEND_CORK_DURATION 을 20 µs 에서 200 µs 로 늘렸다. 50 µs 는 클라이언트 CPU 가 3배였고 320만에서 소켓이 끊겼다(위 표).
    • 상한의 의미 : 송신 간격이 고르면 "가장 오래된 send 가 200 µs 를 넘기면 다음 send 때 보낸다" 가 그대로 지켜진다. 빠르던 송신이 갑자기 느려지면 한 간격(최대 32 send)만큼 늦을 수 있다.
  • 테스트 : linux_io.send_cork_sends_old_responses_{gather,buffered}(test_linux_io.cpp). 32 B × 24 개를 한 버퍼로 보내면, 서버가 echo 뒤 100 µs 씩 일하는 약 2.4 ms 동안 응답이 나뉘어 와야 한다(1 ms 이상 퍼짐). 나이 flush 를 끈 빌드에서는 두 테스트 모두 실패하는 것을 확인했다.

교훈

  • 처리량과 CPU 를 같이 잰다. 회당 160만 개까지는 처리량이 같아 처리량 표로는 회귀가 보이지 않았다. 메시지당 CPU 는 처음부터 두 배였다.
  • 패턴마다 다르다. ping-pong · pipeline 지연 벤치에서는 두 원인 모두 잡음 안이었다. 한 이벤트에 수만 개가 몰리는 큰 묶음 push 를 회귀 벤치에 넣어야 한다.
  • 하나를 고치면 다시 잰다. 수신 수정(r11371) 뒤 재측정에서야 송신 쪽 원인이 드러났다. r11371 만으로는 320만에서 오히려 더 많이 끊겼다.
  • 한 장비에서 서버와 클라이언트를 돌리면 서로 깎는다. 회귀는 클라이언트 쪽(작은 조각 수신)에서 더 컸고, 클라이언트 CPU 가 포화되자 서버 처리량도 떨어졌다.
  • 송신 큐 한도와 처리 능력은 따로 본다. 기본 8 MB 한도면 회당 100만 개 이상에서 한도가 먼저 걸린다. 이 측정은 클라이언트 한도를 32 MB 로 올려 분리했다.
  • strace 는 횟수만 본다. 붙이면 처리량이 절반 가까이 떨어지므로 메시지당 횟수로 비교한다.

bench_server_main.cpp (펼치기) 
// bench_server_main : headless examples/1.1.tcp_echo server (the same echo socket : net::socket::tcp_buffered<>)
//   usage: bench_echo_server <port> <seconds>
#include "cgdk/sdk10/net.socket.h"

#include <chrono>
#include <cstdio>
#include <cstdlib>
#include <thread>

using namespace CGDK;

class socket_tcp_buffered : public net::socket::tcp_buffered<>
{
	virtual result_code on_message(sMESSAGE_NETWORK& _msg) override
	{
		// 1) echo send
		this->send(_msg.buf_message);

		// return)
		return eRESULT::DONE;
	}
};

int main(int argc, char** argv)
{
	const int port = (argc > 1) ? std::atoi(argv[1]) : 20000;
	const int seconds = (argc > 2) ? std::atoi(argv[2]) : 60;

	auto pacceptor = make_own<net::acceptor<socket_tcp_buffered>>();
	if (pacceptor->start({ { net::ip::tcp::v4(), static_cast<uint16_t>(port) } }) != eRESULT::SUCCESS)
	{
		std::printf("acceptor failed\n");
		return 1;
	}
	std::printf("ready port=%d\n", pacceptor->local_endpoint().port());
	std::fflush(stdout);

	std::this_thread::sleep_for(std::chrono::seconds(seconds));

	const auto& statistics = net::io::statistics::Nsocket::statistics_get_traffic_info_total();
	std::printf("server received=%llu sent=%llu failed=%llu\n", static_cast<unsigned long long>(statistics.count_received_message.load()), static_cast<unsigned long long>(statistics.count_sent_message.load()), static_cast<unsigned long long>(statistics.count_error_on_send.load()));
	std::fflush(stdout);
	pacceptor->stop();
	std::_Exit(0);
}
bench_client_main.cpp (펼치기) 
// bench_client_main : headless driver of examples/1.1.tcp_echo client (echo_client.cpp of the example as it is)
//   usage: bench_echo_client <host> <port> <sockets> <window> <seconds> <relay|push> [queue_bytes]
//   - relay : each socket sends <window> 8 byte messages at once, then sends back every echoed message (self clocking : the queues do not grow)
//   - push  : the traffic test of the example (each tick sends <window> messages per socket when the previous round is done)
//   prints the received messages/s of each second and the summary (avg / min / max, sent, failed, sockets)
#include "pch.h"
#include "echo_client.h"

#include <chrono>
#include <cstdio>
#include <cstdlib>
#include <string>
#include <thread>
#include <vector>

extern own_ptr<test_tcp_echo_client> g_ptest_tcp_echo_client;

int main(int argc, char** argv)
{
	const std::string host = (argc > 1) ? argv[1] : "127.0.0.1";
	const std::string port = (argc > 2) ? argv[2] : "20000";
	const int sockets = (argc > 3) ? std::atoi(argv[3]) : 100;
	const int window = (argc > 4) ? std::atoi(argv[4]) : 200;
	const int seconds = (argc > 5) ? std::atoi(argv[5]) : 10;
	const std::string mode = (argc > 6) ? argv[6] : "relay";
	const long long queue_bytes = (argc > 7) ? std::atoll(argv[7]) : 0;	// - 0 : default send queue limit
	if (queue_bytes > 0)
		net::io::sendable::Itcp_gather::default_maximum_queued_bytes(static_cast<std::size_t>(queue_bytes));

	g_ptest_tcp_echo_client = make_own<test_tcp_echo_client>();
	g_ptest_tcp_echo_client->start();
	g_ptest_tcp_echo_client->set_endpoint(host, port);

	// 1) connect
	g_ptest_tcp_echo_client->request_connect(sockets);
	{
		const auto time_end = std::chrono::steady_clock::now() + std::chrono::seconds(20);
		while (static_cast<int>(g_ptest_tcp_echo_client->m_pconnector_socket->count()) < sockets && std::chrono::steady_clock::now() < time_end)
			std::this_thread::sleep_for(std::chrono::milliseconds(10));
	}
	const int connected = static_cast<int>(g_ptest_tcp_echo_client->m_pconnector_socket->count());
	if (connected < sockets)
	{
		std::printf("RESULT error=connect connected=%d/%d\n", connected, sockets);
		return 1;
	}

	// 2) traffic (message 8 byte : index 0 of the example)
	if (mode == "relay")
	{
		g_ptest_tcp_echo_client->enable_relay_echo_test(true);
		g_ptest_tcp_echo_client->request_send_immidiately(window);
	}
	else
	{
		g_ptest_tcp_echo_client->set_traffic_test_count_per_single(window);
		g_ptest_tcp_echo_client->enable_traffic_test(true);
	}

	// 3) measure (warm up 2 seconds)
	const auto& statistics = net::io::statistics::Nsocket::statistics_get_traffic_info_total();
	std::this_thread::sleep_for(std::chrono::seconds(2));

	auto last_sent = statistics.count_sent_message.load();
	auto last_received = statistics.count_received_message.load();
	const auto begin_sent = last_sent;
	const auto begin_received = last_received;
	const auto begin_bytes_received = statistics.count_received_bytes.load();
	const auto begin_failed = statistics.count_error_on_send.load();
	auto last_tick = std::chrono::steady_clock::now();
	const auto begin_tick = last_tick;

	// - the measuring window (the runner reads the CPU times of the processes at these marks)
	std::printf("MEASURE_BEGIN\n");
	std::fflush(stdout);

	std::vector<double> per_second;
	for (int s = 0; s < seconds; ++s)
	{
		std::this_thread::sleep_until(last_tick + std::chrono::seconds(1));
		const auto now = std::chrono::steady_clock::now();
		const auto sent = statistics.count_sent_message.load();
		const auto received = statistics.count_received_message.load();
		const double dt = std::chrono::duration<double>(now - last_tick).count();
		per_second.push_back((received - last_received) / dt);
		std::printf("  t=%2d recv/s=%12.0f sent/s=%12.0f sockets=%zu\n", s + 1, (received - last_received) / dt, (sent - last_sent) / dt, g_ptest_tcp_echo_client->m_pconnector_socket->count());
		std::fflush(stdout);
		last_sent = sent;
		last_received = received;
		last_tick = now;
	}

	std::printf("MEASURE_END\n");
	std::fflush(stdout);

	// - the runner reads the CPU times now : keep the traffic for a moment
	std::this_thread::sleep_for(std::chrono::milliseconds(1500));

	const double total = std::chrono::duration<double>(last_tick - begin_tick).count();
	double min_v = per_second.empty() ? 0 : per_second[0], max_v = min_v;
	for (auto v : per_second) { if (v < min_v) min_v = v; if (v > max_v) max_v = v; }
	const auto failed = statistics.count_error_on_send.load() - begin_failed;
	std::printf("RESULT mode=%s sockets=%d window=%d : recv_msg/s=%.0f sent_msg/s=%.0f min=%.0f max=%.0f failed=%llu sockets_end=%zu\n",
		mode.c_str(), sockets, window,
		(last_received - begin_received) / total, (last_sent - begin_sent) / total,
		min_v, max_v, static_cast<unsigned long long>(failed), g_ptest_tcp_echo_client->m_pconnector_socket->count());
	std::fflush(stdout);

	// 4) stop
	g_ptest_tcp_echo_client->enable_relay_echo_test(false);
	g_ptest_tcp_echo_client->enable_traffic_test(false);
	g_ptest_tcp_echo_client->request_closesocket_all();
	std::this_thread::sleep_for(std::chrono::milliseconds(500));
	g_ptest_tcp_echo_client->stop();
	std::_Exit(0);
}
