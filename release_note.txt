2026.10.25 - Redis 타입 기반 배치 API와 동기 실행, 비교 벤치마크
- 문제: 기존 pipeline은 송신을 묶어도 명령마다 query 생성, 세션 선택, 큐 등록, 완료 통지를 반복했다.
  - 명령 문자열 하나는 단건, 명령 문자열의 배열/벡터/span/initializer_list는 배치로 선택하는 오버로드를 추가했다.

  - 수락된 비동기 배치 callback은 큐/querier 락 밖에서 한 번 호출한다. 동기 세션 할당 대기의 취소/전송 실패는 기존 동기 함수처럼 예외가 발생할 수 있다.

2026.10.26 - Redis 세션 처리 분산, 응답 옵션과 최종 비교 (r11623)
- 공개 동기/배치 이름을 execute_query로 통합. coroutine은 작성 편의성을 위한 API이며 기본 Redis I/O executor 및 외부 executor 선택을 지원한다.
- query의 m_buffer_query/m_lockable_state_query를 제거하고 요청 세대/원자적 완료 상태와 atomic wait/notify로 중복 완료·재사용을 제어한다. 요청 버퍼는 세션 요청 항목이 소유한다.
- 명령 입력은 호출 중 소유하고 세션에서 전송 직전 묶어 인코딩한다. circular_list 송신/미전송 큐를 유지하고 개별 응답은 도착 즉시 처리한다. 전체 응답을 기다리는 vector 큐 방식은 사용하지 않는다.
- start에서 공유 연결 목록을 고정하고 stop에서 접근을 닫는다. 정상 공유 요청의 연결 선택은 querier mutex 대신 세션 접근 가드/TLS 캐시를 사용한다. 전용·관리·대기열 동기화는 유지한다.
- RESP는 memchr 기반 파서를 적용하고 명시적 batch 수신은 최대256개 응답 매칭/통계를 묶는다. AVX2는 실제 경로에서 채택하지 않았다.

- Redis 자동 send_cork 및 전용 설정/벤치 옵션을 제거. 공용 TCP 기능과 send_defer 설정은 유지한다.
